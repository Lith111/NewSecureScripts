### المهمة الأولى: إعداد بيئة المشروع وهيكلة التطبيق

**الهدف:** تأسيس مشروع Django مع المكتبات الأساسية وتهيئة التطبيقات الرئيسية.

**ماذا ستفعل بالتفصيل:**
- إنشاء بيئة افتراضية وتثبيت الحزم: `django`, `djangorestframework`, `django-cors-headers`, `djangorestframework-simplejwt`, `drf-spectacular`.
- إنشاء مشروع `secure_platform` وتطبيقات: `accounts`, `courses`, `progress`, `quizzes`.
- إعداد `settings.py` بإضافة التطبيقات إلى `INSTALLED_APPS` وتكوين `REST_FRAMEWORK` و `CORS`.

**مخرجات المهمة الأولى:**
- مشروع Django يعمل على خادم التطوير.
- التطبيقات الأربعة مسجلة وجاهزة لإضافة النماذج.
- لوحة الإدارة الافتراضية متاحة على `/admin` (بدون تخصيص بعد).

### المهمة الثانية: بناء نظام المستخدمين والمصادقة (مع تخصيص لوحة إدارة المستخدمين)

**الهدف:** إنشاء نموذج مستخدم مخصص، وواجهات API للمصادقة، **وتخصيص واجهة الأدمن لإدارة المستخدمين فوراً**.

**ماذا ستفعل بالتفصيل:**

**النماذج والـ API:**
- إنشاء نموذج `CustomUser` في `accounts/models.py` يرث من `AbstractUser` مع حقل `role` بخيارات `learner` و `admin`.
- تنفيذ `UserSerializer` و `RegisterView` على المسار `api/register/`.
- إعداد مسارات JWT (`api/token/`, `api/token/refresh/`) و `api/me/`.
- إنشاء صلاحيات مخصصة (`IsAdminUser`, `IsLearnerUser`).

**تخصيص لوحة إدارة Django للمستخدمين (في نفس المهمة):**
- في `accounts/admin.py`، إنشاء صنف `CustomUserAdmin` يرث من `UserAdmin`.
- تخصيص `list_display` ليشمل `email`, `username`, `role`, `is_active`, `date_joined`.
- إضافة `list_filter` لتصفية المستخدمين حسب `role` و `is_active`.
- إضافة `search_fields` للبحث بالاسم والبريد الإلكتروني.
- إضافة `fieldsets` لتجميع الحقول (معلومات شخصية، صلاحيات، تواريخ مهمة).
- تسجيل النموذج المخصص مع هذا الصنف.

**مخرجات المهمة الثانية:**
- واجهات API للمصادقة تعمل عبر Postman.
- عند دخول الأدمن إلى لوحة الإدارة (`/admin`)، يجد قسم "Accounts" مع عرض متقدم للمستخدمين، ويمكنه تعديل دور أي مستخدم من `learner` إلى `admin` والعكس.

### المهمة الثالثة: بناء نماذج الدروس وواجهات المتعلم (مع تخصيص لوحة إدارة الدروس)

**الهدف:** إنشاء نموذج الدرس، وواجهة API لعرض الدروس مع منطق القفل التسلسلي، **وفي نفس الوقت تخصيص واجهة الأدمن لإدارة محتوى الدرس**.

**ماذا ستفعل بالتفصيل:**

**النماذج والـ API:**
- في `courses/models.py`، إنشاء نموذج `Lesson` بالحقول: `order`, `title`, `theory_content`, `vulnerable_code`, `secure_code`, `is_published`.
- في `progress/models.py`، إنشاء نموذج `Progress` بالحقول: `user`, `lesson`, `status` (locked/active/completed)، مع `unique_together`.
- بناء `LessonListSerializer` و `LessonDetailSerializer`.
- بناء `LessonListView` و `LessonDetailView` مع تطبيق منطق القفل (لا يمكن طلب درس إلا إذا كان `active` أو `completed`).
- إضافة دالة تلقائية لتحديث حالة `Progress` عند إكمال درس لفتح التالي.

**تخصيص لوحة إدارة Django للدروس (في نفس المهمة):**
- في `courses/admin.py`، إنشاء صنف `LessonAdmin`.
- تخصيص `list_display`: `order`, `title`, `is_published`, `created_at`.
- جعل `list_editable` يحتوي على `is_published` لتغيير حالة النشر مباشرة من صفحة القائمة.
- استخدام `fieldsets` لتقسيم صفحة التحرير:
    - قسم "معلومات أساسية": `title`, `order`, `is_published`.
    - قسم "المحتوى النظري": `theory_content` (مع دمج محرر نصوص غني مثل `django-ckeditor`).
    - قسم "الأكواد البرمجية": `vulnerable_code` و `secure_code` مع إضافة CSS مخصص لجعلها بخط `monospace` وخلفية داكنة.
- إضافة `search_fields` للبحث بالعنوان.
- إضافة `ordering` حسب `order`.

**مخرجات المهمة الثالثة:**
- يمكن للمتعلم عبر API رؤية الدروس المتاحة له حسب حالته.
- في لوحة الأدمن، عند فتح صفحة إضافة/تعديل درس، تظهر الأقسام الثلاثة بشكل منظم، مع محرر نصوص غني للشرح، وحقول نصية واسعة للأكواد.
- يمكن للأدمن إنشاء دروس جديدة بسهولة واستخدامها لاختبار واجهة المتعلم.

### المهمة الرابعة: بناء نظام الفحوصات (مع تخصيص لوحة إدارة الفحوصات داخل صفحة الدرس)

**الهدف:** إنشاء نماذج الفحوصات والأسئلة، وواجهة API لتقديم الإجابات، **وتخصيص لوحة الأدمن بحيث تظهر إدارة الفحص كجزء مدمج داخل صفحة تعديل الدرس**.

**ماذا ستفعل بالتفصيل:**

**النماذج والـ API:**
- في `quizzes/models.py`، إنشاء `Quiz` (مرتبط بـ `Lesson` بعلاقة OneToOne)، و `Question`، و `Choice`، و `UserQuizAttempt`.
- بناء `QuizSerializer` و `QuizSubmissionSerializer`.
- بناء واجهة `QuizView` (GET لعرض الأسئلة، POST لتقديم الإجابات).
- تطبيق منطق التصحيح وتحديث `Progress` عند النجاح.

**تخصيص لوحة إدارة Django للفحوصات (في نفس المهمة):**
- في `quizzes/admin.py`:
    - إنشاء `ChoiceInline` (يرث من `admin.TabularInline`) لتحرير الخيارات داخل صفحة السؤال.
    - إنشاء `QuestionInline` (يرث من `admin.StackedInline` أو `TabularInline`) ويحتوي بداخله على `ChoiceInline`.
- **دمج إدارة الفحص في صفحة الدرس:** بدلاً من جعل `Quiz` يظهر كقسم منفصل، سنقوم بإضافة `QuestionInline` مباشرة إلى `LessonAdmin` باستخدام تقنية `inlines` بعد تعديل العلاقة.
    - سنقوم بإنشاء نموذج `Quiz` كـ OneToOne مع `Lesson`. ثم في `LessonAdmin`، نضيف `inlines = [QuestionInline]` مع تجاوز بسيط بحيث يحصل على `quiz` المرتبط بالدرس (إنشاؤه تلقائياً إذا لم يوجد).
- إضافة حقل `passing_score` إلى `Quiz`، ويمكن عرضه في `LessonAdmin` عبر `fieldsets`.

**مخرجات المهمة الرابعة:**
- واجهة API للفحص تعمل، والمتعلم يمكنه تقديم إجابات ورؤية النتيجة.
- **في لوحة الأدمن:** عند فتح صفحة تعديل درس، يوجد أسفل أقسام الدرس قسم "أسئلة الفحص" حيث يمكن للأدمن إضافة سؤال جديد، وإضافة خيارات لكل سؤال، وتحديد الإجابة الصحيحة عبر مربع اختيار. كل ذلك من نفس صفحة الدرس دون الحاجة للتنقل.

### المهمة الخامسة: تحسينات الأمان والأداء والتوثيق (مع لمسات نهائية للوحة الإدارة)

**الهدف:** ضمان حماية النظام من الثغرات، وتحسين أداء الاستعلامات، وإعداد توثيق API، **وإضافة لمسات نهائية على لوحة الإدارة لتجربة مستخدم ممتازة**.

**ماذا ستفعل بالتفصيل:**

**الأمان والأداء:**
- تطهير محتوى `theory_content` باستخدام `bleach` لمنع XSS.
- استخدام `select_related` و `prefetch_related` في الـ Views لتقليل عدد استعلامات SQL.
- إعداد CORS بدقة.
- إخفاء مسار `/admin/` الحقيقي عبر تغييره في `urls.py` إلى مسار يصعب تخمينه.

**توثيق API:**
- إعداد `drf-spectacular` وإنشاء مسارات `/api/schema/` و `/api/docs/`.

**اللمسات النهائية للوحة الإدارة:**
- تثبيت مكتبة `django-admin-interface` لإضفاء طابع عصري على كامل لوحة الإدارة (ألوان مخصصة، شعار، تخطيط أفضل).
- إضافة إحصائيات سريعة إلى الصفحة الرئيسية للأدمن عبر توسيع قالب `admin/index.html` (عدد المتعلمين، عدد الدروس، نسبة الإكمال).
- تخصيص عناوين الصفحات والتطبيقات في `apps.py` باستخدام `verbose_name`.

**مخرجات المهمة الخامسة:**
- تقرير أمان أولي يظهر خلو النظام من ثغرات IDOR و XSS.
- واجهة Swagger تفاعلية تعرض جميع نقاط النهاية.
- لوحة الإدارة تبدو احترافية: ألوان متناسقة، شعار المنصة، إحصائيات سريعة، وتجربة سلسة لإدارة المحتوى.
