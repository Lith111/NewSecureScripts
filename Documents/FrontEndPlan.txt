### **المرحلة الأولى: إعداد هيكلية المشروع وتهيئة الأدوات (Setup & Architecture)**

في هذه المرحلة، نبني الأساس الصلب للمشروع والذي سيسهل علينا التوسع لاحقاً، وندعم فيها إضافة الصفحة الرئيسية الجديدة.

**النشاط الأول: تهيئة المشروع باستخدام Vite.**
نبدأ بإنشاء المشروع باستخدام أداة Vite وليس Create React App، لأنها أسرع وأكثر توافقاً مع Tailwind. نختار قالب React + JavaScript (أو TypeScript إن كنت تفضل المنع الصارم للأخطاء). بعد إنشاء المشروع، نقوم بتثبيت الحزم الأساسية دفعة واحدة:
- `react-router-dom` للتوجيه بين المسارات، بما فيها مسار الصفحة الرئيسية العام.
- `@reduxjs/toolkit` و `react-redux` لإدارة الحالة.
- `axios` لطلبات الشبكة.
- `react-syntax-highlighter` لعرض الأكواد البرمجية بتنسيق جميل.

**النشاط الثاني: إعداد Tailwind CSS.**
نتبع دليل التثبيت الرسمي لـ Tailwind مع Vite. نقوم بتعديل ملف `tailwind.config.js` لتضمين المسارات الصحيحة للمكونات. نقوم بإنشاء ملف `index.css` يحتوي على التوجيهات الأساسية `@tailwind base; @tailwind components; @tailwind utilities;`. سنستخدم ألواناً مخصصة في المشروع (مثلاً لون أساسي للثغرات، لون للآمن) عبر إضافتها في ملف الإعدادات. نضيف أيضاً ألواناً تُستخدم في أقسام الصفحة الرئيسية مثل: `primary-dark`، `primary-light` و `accent` لإبراز أزرار الدعوة للإجراء.

**النشاط الثالث: تصميم هيكل المجلدات (Folder Structure).**
لضمان نظام قابل للصيانة، نعتمد الهيكل التالي، مع تضمين مجلد خاص بالصفحة الرئيسية:

- `src/`
    - `assets/` (الصور والخطوط)
    - `components/`
        - `common/` (أزرار، نموذج الإدخال، شريط التقدم، Loader)
        - `layout/` (الهيدر، السايدبار، الفوتر، تخطيط الصفحة الرئيسية)
        - `lessons/` (بطاقة الدرس، قفل الدرس، عارض الأكواد)
        - `home/` 
            - `HeroSection.jsx`
            - `FeaturesSection.jsx`
            - `HowItWorksSection.jsx`
            - `CTASection.jsx`
    - `pages/`
        - `auth/` (تسجيل الدخول، التسجيل)
        - `learner/` (لوحة المتعلم، صفحة الدرس، صفحة الفحص)
        - `admin/` (إدارة الدروس، إضافة درس جديد)
        - `home/` **(جديد)**
            - `Homepage.jsx`
        - `errors/` (صفحة 404، صفحة غير مصرح)
    - `redux/` (إدارة الحالة)
        - `slices/` (authSlice, lessonsSlice, progressSlice)
        - `store.js`
    - `services/` (ملفات تكوين Axios ووظائف API)
    - `routes/` (تعريف المسارات ومنطق الحماية)
    - `utils/` (وظائف مساعدة مثل تنسيق التاريخ)

### **المرحلة الثانية: بناء نظام التوجيه ومنطق الحماية (Routing & Guards)**

هنا نطبق مبدأ "الدرس التالي مقفل حتى إنجاز السابق" عبر حماية المسارات، ونضيف مسار الصفحة الرئيسية العام.

**النشاط الأول: تكوين React Router DOM.**
نقوم بلف التطبيق الرئيسي بـ `BrowserRouter`. في ملف `routes/index.jsx`، نعرف مصفوفة كائنات المسارات. نقسمها إلى أربع مجموعات:
1. **مسارات عامة (لأي زائر):**
   - `/` → تعرض صفحة `Homepage` الرئيسية.
   - `/login` → صفحة تسجيل الدخول.
   - `/register` → صفحة إنشاء حساب.
2. **مسارات محمية للمتعلم (`learner`):**
   - `/dashboard` → لوحة تحكم المتعلم.
   - `/lesson/:id` → صفحة عرض الدرس.
   - `/quiz/:lessonId` → صفحة فحص الدرس.
3. **مسارات محمية للأدمن (`admin`):**
   - `/admin/dashboard` → لوحة الأدمن.
   - `/admin/lessons` → إدارة الدروس.
   - `/admin/lessons/create` → إضافة درس جديد.
   - `/admin/lessons/:id/edit` → تعديل درس.
4. **`*` → صفحة 404 (غير موجود).**

نضيف أيضاً منطقاً ذكياً: إذا كان المستخدم قد سجّل الدخول مسبقاً وحاول زيارة `/` أو `/login`، تتم إعادة توجيهه تلقائياً إلى لوحة التحكم الخاصة به (`/dashboard` للمتعلم أو `/admin/dashboard` للأدمن).

**النشاط الثاني: بناء مكون "الحارس" (ProtectedRoute).**
نحتاج إلى مكون وسيط (Wrapper) يعمل كحارس على المسار. وظيفته:
1. التحقق من وجود رمز الوصول (Token) في Redux أو LocalStorage. إذا لم يوجد، يتم التوجيه إلى صفحة تسجيل الدخول مع رسالة "يجب تسجيل الدخول أولاً".
2. التحقق من صلاحية المستخدم (هل هو `learner` أم `admin`). إذا حاول متعلم الدخول لمسار الأدمن، يعاد توجيهه إلى صفحة "غير مصرح".
3. **الأهم: منطق التسلسل الدراسي.** عند طلب مسار `lesson/5`، يقوم الحارس باستدعاء `Selector` من Redux يجلب تقدم المستخدم. إذا كان آخر درس تم إنجازه هو رقم 3 مثلاً، يعاد توجيه المستخدم مباشرة إلى `lesson/4` مع رسالة "أكمل الدرس السابق أولاً".

**النشاط الثالث: التعامل مع التحميل الكسول (Lazy Loading).**
لتحسين الأداء، سيتم تحميل صفحات الأدمن والمتعلم وحتى الصفحة الرئيسية بشكل منفصل باستخدام `React.lazy` و `Suspense`. نضع `fallback` أنيقاً أثناء التحميل.

### **المرحلة الثالثة: إدارة الحالة باستخدام Redux Toolkit (State Management)**

سنبني مخزن مركزي (Store) مقسم إلى شرائح (Slices) لتجنب تعقيد البيانات.

**الشريحة الأولى: Auth Slice.**
تحتوي على الحالة التالية: `user` (بيانات المستخدم المسجل: الاسم، البريد، الصلاحية)، `token`، `isLoading`، و `error`. نقوم ببناء Async Thunk خاص بعملية `login` و `register` لاستدعاء الـ API باستخدام Axios. عند نجاح التسجيل، نخزن التوكن في `localStorage` ونضعه في `header` الافتراضي لـ Axios.

**الشريحة الثانية: Lessons Slice (خاصة بالأدمن).**
تحتوي على قائمة جميع الدروس المضافة في لوحة التحكم. تتضمن Thunks لـ `fetchLessons` و `createLesson` و `updateLesson` و `deleteLesson`.

**الشريحة الثالثة: Progress Slice (قلب النظام).**
هذه هي الشريحة الأكثر أهمية في المشروع. تحتوي على:
- `enrolledLessons`: مصفوفة كائنات، كل كائن يمثل `lessonId` و `status` (مثلاً: `LOCKED`, `ACTIVE`, `COMPLETED`).
- `currentLesson`: بيانات الدرس الذي يشاهده المستخدم حالياً.
- `quizResult`: نتيجة الفحص الأخير.

**العمليات الهامة في هذه الشريحة:**
- `fetchUserProgress`: يجلب من الخادم قائمة الدروس مع حالتها.
- `submitQuizAnswer`: يرسل إجابة الفحص. عند استلام رد `200` من الخادم، نقوم بتحديث حالة الدرس في الـ Slice من `ACTIVE` إلى `COMPLETED`، ونقوم تلقائياً بتحديث الدرس التالي إلى `ACTIVE` في الواجهة الأمامية.

**ملاحظة:** لا نحتاج في الصفحة الرئيسية إلى حالة عامة كبيرة، فهي ستكون صفحة محتوى ثابت (Static) مع إمكانية جلب إحصائيات اختيارية. لذا يمكن الاستغناء عن شريحة إضافية لها، أو إضافة `homepageSlice` بسيط لجلب عدد الدروس المنشورة أو شهادات المستخدمين.

### **المرحلة الرابعة: تطوير الخدمات وتكوين Axios (API Layer)**

سنقوم بإنشاء ملف `services/apiClient.js` لتكوين عميل Axios الأساسي. نقوم بتعيين `baseURL` الخاص بالـ Backend.

**أولاً: إعداد المعترضات (Interceptors).**
- **معترض الطلب (Request):** قبل إرسال أي طلب، يقرأ التوكن من Redux (أو LocalStorage) ويضعه في ترويسة `Authorization: Bearer <token>`. هذا يشمل جميع الطلبات، سواء من صفحات المتعلم أو الأدمن.
- **معترض الاستجابة (Response):** في حال استقبلنا خطأ `401` (غير مصرح)، نقوم بمسح بيانات المستخدم من Redux وتوجيهه تلقائياً إلى صفحة تسجيل الدخول. هذا مهم جداً لأمان الجلسة.

**ثانياً: تنظيم ملفات الخدمات.**
نقوم بإنشاء ملف `services/lessonsService.js` يحتوي على دالة `getLessonById`. هذه الدالة ستجلب تفاصيل الدرس من الخادم (الشرح، الكود الخاطئ، الكود الآمن). كما ننشئ `services/quizService.js` لوظائف تقديم الفحص. نضيف أيضاً `services/homeService.js` (اختياري) لجلب بيانات مثل عدد المتعلمين أو آخر الإحصائيات لعرضها في الصفحة الرئيسية.

### **المرحلة الخامسة: بناء مكونات واجهة المستخدم الأساسية (Core Components)**

سنستخدم Tailwind CSS لبناء واجهة نظيفة وتفاعلية بسرعة، ونضيف مكونات خاصة بأقسام الصفحة الرئيسية.

**المكون الأول: `CodeViewer`.**
بما أن التطبيق يعتمد على عرض أكواد خاطئة وآمنة، سنحتاج لمكون مخصص لعرض الأكواد البرمجية. بما أن Tailwind لا يدعم تمييز الصيغة (Syntax Highlighting) بمفرده، سنقوم بتثبيت مكتبة خفيفة مثل `react-syntax-highlighter` ودمجها مع `tailwind` لضبط الخلفية الداكنة والهوامش. سيكون هذا المكون مسؤولاً عن استقبال نص الكود ولغته (مثل `javascript`, `python`, `sql`) وعرضه بشكل جذاب للمبرمج.

**المكون الثاني: `LessonCard`.**
يعرض في الصفحة الرئيسية للمتعلم (Dashboard). يتميز بثلاث حالات بصرية يتم التحكم بها عبر Tailwind:
- **مكتمل:** لون الحدود أخضر، أيقونة صح، الخلفية فاتحة جداً.
- **نشط (الدرس الحالي):** لون الحدود أزرق، مع تأثير ظل (Shadow) لجذب الانتباه.
- **مقفل:** لون النص رمادي، تأثير تعتيم (Opacity)، يوجد أيقونة قفل، **وإلغاء حدث النقر عليه**.

**المكون الثالث: `LessonLayout`.**
هذا هو تخطيط صفحة الدرس الواحد. يعتمد على نظام الشبكة (Grid) من Tailwind. نقسم الصفحة إلى ثلاثة أقسام رأسية أو أفقية حسب حجم الشاشة. في الأعلى عنوان الدرس، ثم ثلاث بطاقات (Cards) متجاورة:
1. بطاقة "الشرح النظري".
2. بطاقة "الكود الخاطئ" (بخلفية حمراء فاتحة جداً لإيحاء الخطر).
3. بطاقة "الكود الصحيح" (بخلفية خضراء فاتحة جداً لإيحاء الأمان).

في أسفل الصفحة يوجد زر "تقديم الفحص". عند النقر عليه، ينتقل المستخدم إلى صفحة الفحص.

**المكون الرابع: `HeroSection` (خاص بالصفحة الرئيسية).**
مكون يُعرض في أعلى الصفحة الرئيسية، بتصميم كامل العرض (full-width). يحتوي على:
- خلفية متدرجة داكنة (مناسبة لمنصة أمن سيبراني) أو صورة خلفية.
- عنوان رئيسي كبير: "أتقن الأمن السيبراني بتجربة تفاعلية".
- نص وصفي قصير أسفله.
- زرّان للإجراء: زر "ابدأ مجاناً" بحجم كبير وبتأثيرات `hover`، يوجه إلى صفحة التسجيل، وزر ثانوي "كيف تعمل المنصة؟" يمرر المستخدم إلى القسم الثالث (`HowItWorksSection`) باستخدام smooth scroll.

**المكون الخامس: `FeaturesSection` (خاص بالصفحة الرئيسية).**
قسم يعرض مميزات المنصة في ثلاث بطاقات أفقية على الشاشات المتوسطة والكبيرة (`grid grid-cols-1 md:grid-cols-3 gap-8`). كل بطاقة تحتوي على:
- أيقونة SVG بسيطة أو من مكتبة أيقونات.
- عنوان مثل "دروس تفاعلية بأكواد حقيقية"، "نظام قفل/فتح ذكي"، "فحوصات فورية وشهادات".
- نص وصفي قصير.

نصمم البطاقات باستخدام `bg-white dark:bg-gray-800` مع حدود وظلال خفيفة `shadow-md rounded-xl p-6`.

**المكون السادس: `HowItWorksSection` (خاص بالصفحة الرئيسية).**
يعرض الخطوات الأربع لكيفية استخدام المنصة بتصميم جدول زمني أو شبكة مرقمة. نستخدم `flex flex-col md:flex-row justify-between items-start` مع خطوط ربط بين الخطوات (يمكن استخدام `before:` pseudo-elements أو مجرد حدود). الخطوات هي:
1. سجّل حساباً.
2. اختر مساراً تعليمياً.
3. ادرس الدرس، وشاهد الكود الخاطئ والصحيح.
4. اجتز الفحص وافتح الدرس التالي.

كل خطوة تحتوي على رقم كبير وعنوان ونص توضيحي.

**المكون السابع: `CTASection` (خاص بالصفحة الرئيسية).**
قسم ختامي لدعوة المستخدم للتسجيل. يتميز بخلفية بلون رئيسي داكن (`primary-dark`) مع نص مركزي: "جاهز لتصبح خبيراً في الأمن السيبراني؟". وزر كبير بارز: "سجّل الآن الآن" بتأثير `hover:scale-105 transition-transform`. يمكن إضافة إحصائيات افتراضية أسفله مثل: "+5000 متعلم" و "+100 درس تفاعلي".

**المكون الثامن: مكونات التخطيط العام (`Header` و `Footer`).**
- **الهيدر (Header):** يختلف حسب حالة تسجيل الدخول. إذا كان المستخدم زائراً، يظهر روابط: الرئيسية، تسجيل الدخول، التسجيل. إذا كان مسجلاً، يظهر اسم المستخدم وروابط لوحة التحكم وتسجيل الخروج. نستخدم `sticky top-0` مع خلفية شفافة جزئياً.
- **الفوتر (Footer):** بسيط مع حقوق النشر وروابط سريعة.

### **المرحلة السادسة: بناء صفحات المتعلم الرئيسية (Learner Pages)**

**الصفحة الأولى: لوحة التحكم (Dashboard).**
هنا نستخدم `useSelector` لسحب `enrolledLessons` من Redux. نقوم بعمل `map` على المصفوفة ونعرض `LessonCard` لكل درس. نضيف مكون شريط التقدم العام (Progress Bar) في أعلى الصفحة باستخدام Tailwind. يمكن تنفيذ شريط التقدم بسهولة عبر عنصر `div` بخلفية رمادية، وبداخله `div` آخر عرضه يحسب كنسبة مئوية: `(عدد الدروس المكتملة / إجمالي الدروس) * 100%`.

**الصفحة الثانية: عرض الدرس (Lesson View).**
عندما ينقر المستخدم على الدرس النشط، ينتقل إلى مسار `lesson/:id`. هنا نستخدم `useParams` للحصول على المعرف. نستدعي `useEffect` الذي بدوره يطلب بيانات الدرس من الـ API عبر Redux Thunk. **التحقق الأمني الإضافي:** قبل عرض البيانات، يجب أن نتحقق من أن `lessonId` المطلوب يساوي `currentActiveLessonId` المخزن في Redux. إذا حاول المستخدم تعديل الرابط يدوياً إلى درس أعلى، نعيد توجيهه مباشرة إلى لوحة التحكم مع رسالة تحذير.

**الصفحة الثالثة: فحص الدرس (Quiz).**
صفحة مخصصة تعرض سؤال الفحص الذي أدخله الأدمن. عادة ما يكون سؤال اختيار من متعدد. نستخدم `Radio Buttons` مخصصة بـ Tailwind. عند تقديم الإجابة، نستدعي `submitQuizAnswer`. نعرض للمستخدم رسالة فورية: إما نجاح (يتم تحويله تلقائياً للدرس التالي بعد ثانيتين) أو رسوب (يعرض له سبب الرسوب ويعيده لصفحة الدرس للمراجعة).

### **المرحلة السابعة: بناء صفحة `Homepage` الرئيسية وتجميع أقسامها الأربعة**

الهدف من هذه المرحلة هو إنشاء صفحة رئيسية جذابة من أربعة أقسام، تكون هي أول ما يراه الزائر، وتعرّف بالمنصة وتحفّز على التسجيل.

**النشاط الأول: إنشاء ملف الصفحة الرئيسية `Homepage.jsx`.**
داخل `pages/home/`، ننشئ مكون `Homepage.jsx` بالهيكل التالي:
- استيراد مكونات الأقسام الأربعة: `HeroSection`, `FeaturesSection`, `HowItWorksSection`, `CTASection` من `components/home/`.
- استيراد `Header` و `Footer` من `components/layout/` (سيُستخدمان أيضاً في باقي الصفحات عبر `Layout` عام).
- نلف المحتوى داخل `div` رئيسي مع `overflow-x-hidden` ثم نضيف الأقسام بالترتيب: الهيدر، ثم البطل، ثم المميزات، ثم كيف تعمل، ثم الدعوة للإجراء، ثم الفوتر.
- بما أن الصفحة ثابتة غالباً، لا نحتاج إلى `useEffect` لجلب بيانات، ولكن يمكن تجهيز الدوال للاتصال بـ API إحصائيات لو أردنا.

**النشاط الثاني: تنفيذ القسم الأول – `HeroSection`.**
نبني مكون `HeroSection.jsx` في `components/home/`. نستخدم `section` بعرض كامل مع `h-screen` أو `min-h-screen`، وخلفية متدرجة داكنة من أعلى إلى أسفل (`bg-gradient-to-b from-gray-900 to-gray-800`)، ومحتوى نصي في المنتصف تماماً باستخدام `flex flex-col items-center justify-center text-center px-4`. نضيف عنواناً (`h1`) كبيراً بحجم `text-5xl md:text-6xl font-extrabold text-white`، وفقرة وصفية أسفله بـ `text-lg text-gray-300 max-w-2xl`. ثم نضيف الأزرار:
- زر "ابدأ مجاناً": `Link` من `react-router-dom` إلى `/register`، بتصميم `bg-accent hover:bg-accent-dark text-white font-bold py-3 px-8 rounded-full shadow-lg transition transform hover:scale-105`.
- زر "كيف تعمل المنصة": عنصر `<button>` أو `<a>` يستخدم `scroll-behavior: smooth` للانتقال إلى معرّف `#how-it-works`.

**النشاط الثالث: تنفيذ القسم الثاني – `FeaturesSection`.**
ننشئ `FeaturesSection.jsx`. نعطيه `id="features"` للرجوع إليه عند الحاجة. نضع حاوية `max-w-7xl mx-auto px-4 py-16 md:py-24`. نضيف عنواناً رئيسياً للقسم: "لماذا منصتنا؟" بتنسيق `text-3xl md:text-4xl font-bold text-center mb-12`. ثم نضع شبكة البطاقات الثلاث. نكرر على مصفوفة كائنات (ثابتة داخل المكون) تحتوي كل منها على: `icon` (مكون SVG)، `title`، `description`. نستخدم `map` لعرض كل بطاقة في `div` مع التنسيقات المذكورة سابقاً. نضيف أيقونات SVG بسيطة يدوياً أو نستعين بمكتبة `react-icons` إذا أردنا، لكن الأفضل استخدام SVG مضمنة لتقليل الاعتماديات.

**النشاط الرابع: تنفيذ القسم الثالث – `HowItWorksSection`.**
ننشئ `HowItWorksSection.jsx` بمعرّف `id="how-it-works"`. نستخدم خلفية فاتحة قليلاً (`bg-gray-50 dark:bg-gray-900`) لتمييزه عن الأقسام الأخرى. نضيف حاوية مماثلة مع عنوان: "كيف تبدأ رحلتك التعليمية؟" ونص فرعي. ثم ننشئ حاوية للخطوات باستخدام `flex flex-col md:flex-row gap-8`، وكل خطوة في `div` يحتوي على دائرة أو مربع كبير للرقم (مصمم بـ `w-12 h-12 rounded-full bg-primary text-white flex items-center justify-center text-2xl font-bold`)، ثم عنوان الخطوة ونصها. بين الخطوات يمكن إضافة سهم أو خط فاصل باستخدام عنصر `div` مخفي على الشاشات الصغيرة ويظهر على الكبيرة (`hidden md:block w-8 h-0.5 bg-gray-300 self-center`). ننتبه إلى جعل تصميم الخطوات سهل القراءة ومفهوماً.

**النشاط الخامس: تنفيذ القسم الرابع – `CTASection`.**
ننشئ `CTASection.jsx` بخلفية بلون رئيسي قوي (`bg-primary-dark`)، ونص أبيض في المنتصف: `text-center py-16 md:py-24`. نضيف نصاً كبيراً: "جاهز لتصبح خبيراً في الأمن؟" ثم فقرة صغيرة، ثم زر التسجيل الذي يحاكي تصميم زر القسم الأول ولكن بلون متباين (مثلاً أبيض مع نص بلون رئيسي). نضيف تحت الزر صفاً به إحصائيات مختصرة مثل: "أكثر من 5000 متعلم" و "أكثر من 100 درس تفاعلي". نستخدم شبكة صغيرة `grid grid-cols-2 gap-4 mt-8` لعرضها.

**النشاط السادس: إعداد التمرير السلس (Smooth Scroll) للزر داخل `HeroSection`.**
في `index.css` أو عبر إضافة `scroll-behavior: smooth;` لعنصر `html`. نربط زر "كيف تعمل المنصة" بمعرّف `#how-it-works` عبر `onClick` الذي يستخدم `document.getElementById('how-it-works').scrollIntoView({ behavior: 'smooth' })`. أو نستخدم `<a href="#how-it-works">` مباشرة وسيعمل تلقائياً بفضل `scroll-behavior`.

**النشاط السابع: دمج الهيدر والفوتر في الصفحة الرئيسية.**
نتأكد من أن مكونات `Header` و `Footer` تستجيب لحالة تسجيل الدخول التي نحصل عليها من `useSelector(authState)`. في `Header`، نعرض:
- إذا لم يكن هناك مستخدم: روابط: الرئيسية (`/`)، تسجيل الدخول (`/login`)، إنشاء حساب (`/register`).
- إذا كان المستخدم `learner`: لوحة التحكم (`/dashboard`) وزر تسجيل الخروج.
- إذا كان `admin`: لوحة الأدمن (`/admin/dashboard`) وزر تسجيل الخروج.
نستخدم `tailwind` لجعل الهيدر شفافاً جزئياً على الصفحة الرئيسية ومصمتاً في باقي الصفحات، وذلك عبر تمرير `prop` أو بالاعتماد على المسار الحالي من `useLocation`.

### **المرحلة الثامنة: تحسينات الأداء وتجربة المستخدم (Optimization)**

**أولاً: التعامل مع حالات التحميل والأخطاء.**
سنقوم بإنشاء مكون `Loader` عبارة عن سبينر باستخدام Tailwind Animations. سيظهر في أي مكان ننتظر فيه استجابة من API (مثل تسجيل الدخول، تحميل الدرس، تقديم الفحص). نستخدم مكون `ErrorBoundary` عام لتغليف التطبيق لمنع انهيار الواجهة بالكامل. نضيف أيضاً صفحات أخطاء مخصصة: `NotFound404` (مع زر العودة للرئيسية) و `Unauthorized` (مع إعادة توجيه).

**ثانياً: استمرارية الجلسة (Persist State).**
حتى لا يضطر المستخدم لتسجيل الدخول كل مرة يقوم فيها بتحديث الصفحة، سنستخدم مكتبة `redux-persist`. سنقوم بإعدادها لتخزين بيانات `Auth` و `Progress` في `localStorage` بشكل مشفر (أو على الأقل غير قابل للتلاعب بسهولة). عند تحميل التطبيق، يتم استرجاع الحالة تلقائياً مما يحافظ على تقدم المستخدم. هذا مهم أيضاً كي لا يفقد المتعلم تقدمه إذا أغلق المتصفح فجأة.

**ثالثاً: معالجة المسارات غير الموجودة.**
صفحة 404 مخصصة برسالة "الصفحة غير موجودة" أو "الدرس غير موجود" مع زر للعودة للوحة التحكم أو الصفحة الرئيسية، مصممة بـ Tailwind بأسلوب مرح وجذاب.

**رابعاً: تحسين أداء الصفحة الرئيسية.**
نحرص على تحميل الصفحة الرئيسية بشكل سريع عبر استخدام الصور المضغوطة (إن وجدت) وتجنب طلبات الشبكة غير الضرورية. الأيقونات ستكون SVG مضمنة، ولا نحمّل مكتبة أيقونات كاملة إلا إذا لزم الأمر. نستخدم `React.memo` للمكونات الثابتة مثل البطاقات.

### **ملخص تنفيذي للمطور Front-End (مُحدَّث ليشمل الصفحة الرئيسية)**

ابدأ بتنفيذ هذه الخطة أسبوعياً:
1. **الأسبوع 1:** تثبيت React + Tailwind + Router. بناء هيكل المجلدات. البدء بصفحات Auth (تسجيل الدخول والتسجيل). تصميم الهيدر والفوتر الأساسيين.
2. **الأسبوع 2:** إعداد Redux Store و Auth Slice وربط Axios. إكمال وظائف التسجيل وتسجيل الدخول مع التخزين في LocalStorage.
3. **الأسبوع 3:** بناء الصفحة الرئيسية `Homepage` وأقسامها الأربعة: `HeroSection`، `FeaturesSection`، `HowItWorksSection`، `CTASection`. ربطها بالمسار العام `/`. تطبيق التمرير السلس.
4. **الأسبوع 4:** بناء تخطيط صفحة المتعلم (Dashboard) مع شريط التقدم ومكون `LessonCard`. ربط الدروس بالحالات (LOCKED, ACTIVE, COMPLETED).
5. **الأسبوع 5:** بناء صفحة عرض الدرس (Lesson View) ومكون `CodeViewer`. تطبيق منطق القفل/الفتح في `ProtectedRoute`.
6. **الأسبوع 6:** بناء صفحة الفحص (Quiz) وآلية تقديم الإجابة. ربطها مع Redux وتحديث التقدم تلقائياً.
7. **الأسبوع 7:** بناء لوحة تحكم الأدمن: عرض الدروس، إضافة درس جديد، تعديل وحذف. ربطها مع API.
8. **الأسبوع 8:** التحسينات النهائية: `ErrorBoundary`، `Loader`، `redux-persist`، صفحة 404، اختبار التطبيق وتجربة المستخدم، وإطلاق النسخة التجريبية.
